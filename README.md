# PaxosBus

This repository includes the implementation of PaxosBus, a research prototype for a novel wide area network consensus protocol that batches client requests into periodic buses and uses a shared schedule to establish their order, reducing the coordination needed to order individual requests and allowing requests to complete in nearly one round-trip time (RTT) during normal processing.

## File Structure

<sub>* This project builds on the open-source [SwiftPaxos codebase](https://github.com/imdea-software/swiftpaxos), reusing its protocol implementations as our baselines All PaxosBus-specific code and supporting files are under [`paxosbus/`](paxosbus/)</sub>

- `paxosbus/cmd/`: replica and client entry points
- `paxosbus/docs/`: experiment setup and usage instructions
- `paxosbus/internal/`: protocol, configuration, wire messages, and logging
- `paxosbus/scripts/`: experiment scripts
- `paxosbus/tla/`: TLA+ specifications

## Important Configuration Parameters

The [PaxosBus runner](paxosbus/scripts/run-paxosbus.sh) accepts the following command-line options:

| Option | Default | Description |
| --- | --- | --- |
| `-g`, `--request-interval-us` | 500 μs | Request generation interval per client|
| `-p`, `--bus-interval-ms` | 1 ms | Interval between buses generated by each client |
| `--command-size` | 512 bytes | Payload size of each request |
| `--schedule-window-ms` | 2,000 ms | Length of each scheduling window |
| `-d`, `--duration-s` | 60 s | Duration of the experiment's data phase |
| `--normal`, `--failure` | `--normal` | Either normal processing or trigger a view change 20 seconds in |
